# 운영과 오류 복구

## 기본 규칙

담기 → 목록·수량·비용 검토 → 시작의 순서입니다. 새로 담긴 항목이 기대와 다르면 바로 실행하지 말고 카드 종류와 발생 원인을 확인합니다. 프리셋의 자동 재료 준비, 시설 수령 선택, `overlay_auto_collect`가 선행/수령 항목을 추가할 수 있습니다. 이것만으로 알 수 없는 항목을 버그나 사용자 미입력으로 단정하지 않습니다.

| 상태 | 의미 | 대응 |
|---|---|---|
| pending / stopped | 대기 또는 사용자 중단 | 검토 후 명시적 시작 |
| running | 명령 실행 중 | 응답과 실제 진척 확인 |
| waiting (가공) | 등록된 가공의 완료/빈 칸 대기 | 완료 대기와 큐 종료를 구분 |
| done | 해당 카드 목표 완료 | 새 반복을 임의 추가하지 않음 |
| error | 실패 원인 확인 필요 | 오류별 절차, 무조건 재시도 금지 |

가공 카드의 `progress.done`은 등록 횟수, `progress.got`은 수령 횟수입니다. 게임에 걸어둔 가공 시간은 앱이 명령을 계속 실행하는 시간과 다릅니다. `collect=later`는 등록 목표 달성과 전체 수령 완료가 다를 수 있습니다. 같은 이름의 카드를 새로 만들어 이어가는 대신 기존 ID와 진행량을 보존합니다.

## 1시간 확인창

1. 게임의 실제 확인창을 사용자가 직접 확인합니다.
2. 큐와 다른 명령이 실행 중이지 않은지 확인합니다.
3. 관리의 `게임 확인 후 작업 복구`에서 직접 확인했음을 명시적으로 승인합니다.
4. 제한 오류 카드만 진행량을 유지한 채 대기로 돌아가는지 봅니다. 재료 부족 등 다른 오류는 그대로 남습니다.
5. 작업 목록을 검토하고 시작을 따로 누릅니다. 복구 버튼은 자동 실행하지 않습니다.

이 과정은 사람의 확인 진술을 로컬에 기록하는 것입니다. 게임 확인을 API로 대신 수행하거나 게임 내부 타이머를 검증하지 않습니다. `connector_confirmed` 요청을 자동화하지 마세요.

관찰기가 제한을 감지한 상태에서는 시작 요청을 게임 조회보다 먼저 차단합니다. 앱 재시작이나 휴식으로 그 상태를 임의 초기화하지 않습니다. 완료·오류와 등록된 가공 대기는 재시작 후에도 보존합니다. 실행 중이던 작업이 재시작됐다고 자동 재개되는 것은 아닙니다.

## 다른 오류

- `not_enough_ingredient`: 실제 재료와 선행 생산/수령 여부를 확인. 수량이나 날개 소비가 있는 재실행은 사용자가 결정.
- `unknown_modal`: 게임 화면의 정확한 창을 확인. 가공 대기열 부족 문구로 오분류한 과거 사례가 있어 문자열만 믿지 않음. 자동 확인 클릭 없음.
- 연결/로딩/캐릭터 선택: 앱 시작 성공과 게임 실행 성공은 다름. 정상 접속 확인 후 수동 재시작.
- 30분 무진척 대기 상한: 정상 가공 대기였어도 앱 큐가 종료될 수 있음. 종료 사유를 확인하고 사용자가 재개. 자동 재개 규칙은 현재 없음.
- 불확실한 가공 등록 응답: 이미 결제·등록됐을 가능성이 있어 무조건 동일 등록을 다시 보내지 않음. 시설 상태·진행량 확인 우선.

## 명령 시간 표시

측정 대상은 `execute_gathering`, `execute_crafting`, `execute_altering`, `complete_altering_work`의 완료된 CLI 호출 소요시간입니다. 조회, 시설에서 가공되는 벽시계 시간, 휴식은 합산하지 않습니다. 실행 중 호출은 별도의 대기 추정으로 표시합니다.

- 최초에는 `측정 시작 후 명령 누적`: 그 이전 게임 이용량은 모름.
- 사용자가 직접 확인을 기록하면 `직접 확인 후 명령 누적`: 전체 관찰 합계는 유지하고 표시 기준점만 변경.
- 55분 부근 주의 표시는 관찰 기반 안내. 정확한 게임 차단 시각이나 남은 이용시간 약속이 아님.
- 앱 비정상 종료 시 미완료 호출 누락, 호출 겹침 등은 불완전 표식을 표시. 전체 PC나 다른 앱까지 측정하지 않음.

## 휴식 설정

현재 PC에서 확인한 값은 실험 켜짐, 간격 45분, 휴식 300초입니다. 코드 기본값은 실험 꺼짐, 45분/120초이며 새 설치와 기존 설치는 다를 수 있습니다. 예전에 요청됐던 55분/5분을 현재 적용값으로 혼동하지 마세요.

휴식은 명령이 끝나는 안전 경계에서 시작하므로 45분 정각에 실행 중 채집을 강제 중단하지 않습니다. 전송 억제 준비 시 이미 허용된 호출을 먼저 마친 뒤 실제 휴식이 시작됩니다. 중지 요청은 휴식 대기를 취소하며 후속 게임 조회/실행도 보내지 않습니다.

휴식 토글은 켜짐/꺼짐만 저장하고 기존 간격·길이는 보존합니다. 2분과 5분의 완전한 앱 호출 억제 후에도 제한 재발이 관찰됐으므로 이를 예방책으로 보장하지 않습니다.
