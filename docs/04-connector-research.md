# AI 커넥터 1시간 제한 · 근거와 남은 불확실성

## 결론

2분/5분 동안 이 앱의 모든 CLI 호출을 억제해도 이후 1시간 제한이 재발했습니다. 단순 벽시계 경과보다 **실제 위임 명령 호출 소요시간의 누적**에 가깝다는 가설이 로그를 더 잘 설명합니다. 이는 관찰 기반 추론이며 공식 내부 계산식이 아닙니다.

## 공식적으로 확인되는 범위

- 커넥터가 계속 실행되면 1시간 확인 팝업이 표시되고 사용자가 확인하면 이어갈 수 있습니다. [공식 가이드](https://mabinogimobile.nexon.com/Info/Guide/3545322)
- 10/15 업데이트에는 1시간 확인 팝업이 간헐적으로 표시되지 않던 현상 개선과 작곡 악보의 커넥터 연주 제한이 기재돼 있습니다. [공식 업데이트](https://mabinogimobile.nexon.com/News/Update/3563175)
- 커넥터의 목적과 사용 책임은 [공식 사전 안내](https://mabinogimobile.nexon.com/News/Notice/3541579) 참고.

공식 자료에서 조회가 누적되는지, 몇 분 쉬면 초기화되는지, 내부 계산이 CLI 소요시간과 같은지는 확인하지 못했습니다. 10분 휴식 효과도 검증하지 않았습니다. 예전 장시간 가공 성공을 게임 버그 하나로 설명하지 않습니다.

## 관찰값 (KST)

| 구간 | 시작 → 제한 | 벽시계 | 실제 휴식 | 완료 명령 호출 소요시간 합계 |
|---|---|---:|---:|---:|
| 2분 시험 | 10/23 22:51:40 → 23:54:13 | 3,753초 (62분33초) | 120초 | 채집 3,609.017초 (60분9초), 28회 |
| 5분 시험 | 10/24 05:56:50 → 07:02:13 | 3,923초 (65분23초) | 300초 | 채집 2,451.878 + 제작 1,159.220 = 3,611.098초 (60분11초), 33회 |
| 이전 장시간 쌀 가공 | 10/21 약 00:38:43 → 06:19:36 | 약 5시간41분 | 별도 해석 필요 | 등록 50.748 + 수령 173.610 = 224.358초 (약3분44초) |

로그의 admitted/finished ID를 짝지어 `seconds`를 명령별로 합산했습니다. 일자/PID별 회전 로그 범위와 누락에 영향을 받습니다. 채집/제작 호출의 이동·런처 지연이 포함될 수 있으므로 내부 타이머와 수초 단위 일치를 주장하지 않습니다.

이전 가공 시험은 53회 목표 중 등록 성공 37회, 수령 35회 이후 재료 부족으로 끝난 구간입니다. 5시간 동안 실제 실행 명령이 계속 돌았다는 뜻이 아니고 목표 전체 완료도 아닙니다. 시설의 가공 대기를 대부분 차지한 것으로 해석됩니다.

## 휴식 전송 감사

| 실제 quiet-ready → quiet-ended | 길이 | admitted | finished | suppressed |
|---|---:|---:|---:|---:|
| 10/23 23:38:22 → 23:40:22 | 120초 | 0 | 0 | 7 |
| 10/24 06:42:59 → 06:47:59 | 300초 | 0 | 0 | 19 |

휴식 창의 시작·끝 로그가 모두 존재하는 구간만 무호출 감사에 사용했습니다. `suppressed`는 조회 시도가 로컬에서 차단된 것이며 게임으로 전송된 것이 아닙니다. 끝난 후 실제 채집/제작 성공이 있었고 이후 제한도 재발했습니다. 단순 대기 로그를 성공으로 세지 않았습니다.

## 구현의 의미

`transportquiet.py`는 새 CLI 진입을 닫고, 기존 호출을 배출한 뒤 휴식합니다. status, get_activity, 가공/음악 조회도 동일 transport를 통과하면 차단됩니다. 억제된 호출은 종료 뒤 자동 재전송하지 않습니다.

이 감사는 **이 앱 프로세스**의 호출 경계만 증명합니다. 게임의 AI 환경 설정을 끄지 않으며, 게임 내부 연결/세션이나 다른 프로그램의 통신까지 끊었다는 증거가 아닙니다. 따라서 문서에서 '완전 연결 해제 성공'이라고 부르지 않습니다.

## 채택한 대응과 후속 연구

1. 실제 명령 누적 관찰을 저장·표시하되 게임 타이머와 명확히 구분.
2. 제한이면 멈추고 사용자 직접 확인을 요청. 진행량 보존 복구와 명시적 시작을 분리.
3. 휴식 시간 자동 증가·반복 재시도·확인창 자동 클릭은 하지 않음.
4. 추가 시험은 별도 승인된 목표·시간 범위에서 실시. 시작 시점/직접 확인 시점/프로세스/회전 로그/오류를 함께 보존해야 함.
5. 조회만 장시간 지속, 명령 종류별 차이, 이동 포함 여부는 미검증. 기존 로그 재분석 또는 짧은 모의 테스트와 실제 게임 시험을 구분.

원문 개인 로그는 업로드하지 않았습니다. `tools/analyze-connector-log.py`로 본인 PC에서 재현 분석할 수 있으며 도구는 게임 CLI를 호출하지 않습니다. 장기 추적 자동화는 현재 꺼져 있고 이 정리 작업으로 새로 켜지 않았습니다.
