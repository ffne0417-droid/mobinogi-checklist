# 개발·검증과 미해결 사항

## 이번 적용에서 확인한 것

2026-10-24 현재 PC에서 다음을 검증했습니다.

- action-only 시간 측정, 휴식/조회 제외, 영속 합계, 직접 확인 기준점, 비정상/중복 데이터 표식.
- 제한 상태에서 시작 전에 차단하며 게임 조회도 보내지 않음.
- 직접 확인 복구가 제한 카드 진행량을 보존하고 재료 부족 오류는 그대로 남김. 자동 시작 없음.
- 재시작 후 오류 상태와 가공 대기 보존.
- quiet 진입 전 drain, 휴식 중 모든 transport 호출 차단, 취소, 억제 요청 재전송 없음, 본문 없는 감사 로그.
- 경계 휴식 일정·진행 중/고아 명령 보호·사용자 정지 처리.
- 기록 조회 지연 로딩, 문자 escaping, 중복 mount 방지, 복구 POST 연결과 새로고침.
- 휴식 켜기/끄기가 간격과 길이를 덮어쓰지 않음.
- 관리 화면 520/600/840px에서 기록 열림/닫힘 모두 영역 겹침 없음, 보드 유효 높이 확보.
- 기존 실행 앱을 정상 종료 후 승인된 실행기로 재기동. 전후 카드 전체 내용 동일, 큐 정지 유지, 새 관찰 필드 응답 확인.
- 이관용 Python 테스트 10개와 UI 테스트 3개를 개인 경로가 없는 스냅샷에 대해 재실행해 통과. 설치 스크립트의 계획/적용/백업/데이터 경로 생성을 가짜 설치 폴더에서 검증했으며 실제 새 PC 실행과는 구분.

단위/브라우저 검증은 모의 응답 또는 실제 쓰기 차단을 사용했습니다. 테스트를 위해 유료 채집·제작·가공을 실행하지 않았습니다. 헤드리스 Edge는 샌드박스 프로세스 제한에서 한 차례 시작 실패했고, 허용된 외부 실행으로 동일 모의 UI 테스트를 완료했습니다.

## 저장소의 안전한 선별 테스트

Python 3.12 이상 권장. 프로젝트 루트에서:

```powershell
python -X utf8 tests/qa-connector-usage.py
python -X utf8 tests/qa-transport-quiet.py
python -X utf8 tests/qa-connector-break.py
python -X utf8 tests/qa-connector-limit.py
python -X utf8 tests/qa-queue-history-retry.py
```

UI 테스트는 Node.js와 Playwright를 개발용으로 사용하며 앱 런타임 필수 의존성은 아닙니다.

```powershell
npm install --ignore-scripts
# 설치된 Microsoft Edge 사용. 게임창을 조작하지 않음.
npm test
```

`qa-connector-usage-ui.mjs`, `qa-observation-state.mjs`는 순수 JS 상태 검사입니다. `qa-queue-history-ui.mjs`는 빈 HTML+모의 API를 띄우는 헤드리스 검사입니다. 실제 사용자 데이터/API를 대상으로 한 테스트는 자동 npm test에 넣지 않았습니다.

테스트를 수정할 때 원본 모듈을 불러오는 것만으로 실제 store/CLI가 동작하지 않는지 먼저 확인합니다. 무조건 전체 테스트 파일을 새 PC 게임 실행 중 일괄 실행하지 마세요.

## 미해결·미검증

- 게임의 정확한 1시간 누적 계산식, 조회만의 영향, 세션 만료 조건.
- 10분 이상 휴식의 효과. 실시하지 않았고 성공으로 기록하지 않음.
- 새 PC에서 원본 배포본+이 소스 전체를 합친 실제 게임 통합 동작.
- 모든 화면비/모니터 배치/DPI에서 네이티브 동작. 관리 DOM 검사와 다른 범위.
- 게임 확인 완료를 기계적으로 검증하는 기능. 현재는 사용자가 직접 확인했다고 명시하는 방식.
- 다른 도구의 커넥터 통신. 이 앱의 감사 로그만으로 전체 PC 무통신을 증명할 수 없음.
- 다운로드 사이트의 현재 가용성, 원본 배포본의 전체 재배포 라이선스. 외부 바이너리 자동 다운로드 없음.
- 기존 원본 기능의 전체 회귀. 이번 결과는 나열한 범위이며 모든 조합의 게임 성공을 뜻하지 않음.

## 개발 원칙

원본 UI·API를 재사용하고 별도 큐를 만들지 않습니다. 원인 불명 오류와 결제 불확실 상태는 자동 retry하지 않습니다. 개인 큐를 덮어쓰거나 기본 샘플 작업을 생성하지 않습니다. 변경 전 파일/데이터 백업과 변경 후 읽기 검증을 분리합니다. 민감 응답 본문을 로그에 남기지 않습니다.
